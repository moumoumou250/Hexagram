# 解读 Skill 建议方案（EL15）

状态：**P0/P1 已落地**（`skills/jingfang-06-interpretation/` + `jingfang/interpretation.py`）  
相对原方案 `PLAN-interpretation-skill.md`：砍掉过重的权重体系，强制「给人看的句子必须 EL15」。

---

## 0. 一句话

解卦六步照旧负责「判」；本 Skill 只负责「说清楚」。  
页面上出现的每一句固定话，要让大约 15 岁、没背过章名的人也能看懂：**用神这爻现在怎样、为什么、还要等什么。**

它**不是**第六个解卦步骤。

### 范围硬约束（防误导）

本项目的解读区**只分析用神（及直接相关的原神、忌神、世应结构）**，**不对「所问的具体事情」做故事化解读**。

| 可以说 | 不可以说 |
| --- | --- |
| 用神现在没力。因为月破，又被日克。 | 这次求职一定失败 / 对方不会回头 |
| 原神有力，能生用神。 | 你下个月会升职、会复合、会痊愈 |
| 应期通道：逢冲、填实（候选） | 三月八日对方会打电话来 |

原因：所问事项要落到用神，中间还有取用是否正确、域是否翻转等步骤；程序若直接「断事」，读者会当成人生预言，容易误导。  
`question` 字段只用来**选定用神类别与核对范围**，不作为解读区叙事素材。

## 1. EL15 硬要求（输出必须遵守）

解读区文案（预设规则命中句、程序结论摘要、象标签说明）一律满足：

1. **短句。** 一句一事；单句尽量不超过 28 个汉字。
2. **先结论，后原因。** 例：「用神眼下偏弱。因为月破，又被日克。」
3. **术语必带白话。** 第一次出现可留书名，但必须括号翻译。  
   - 月破 → 被月建冲掉  
   - 暗动 → 安静却被日冲、且本身旺，像被叫醒  
   - 旬空 → 这旬轮空，力量打折  
   - 无根 → 自身站不住，别人来生也难救  
4. **禁止裸甩章名当理由。** 可写出处小字，但不写「据月破章故凶」这类空话。
5. **只谈用神，不谈所问之事的结局。** 禁止「升职/复合/病愈/得财」等事项结果句；只写用神、原神、忌神的力量与条件。
6. **不确定就明说。** 争议条目标「需人工核对」，不装成铁律。
7. **不写具体应验日断言。** 只写通道：逢值 / 逢冲 / 填实 / 当令… 加置信度。

模板句式（`rules.json` 必须用这类槽位，禁止另起文言腔）：

```text
{谁}现在{怎样}。因为{原因}。{例外或下一步}
```

反例 → 正例：

| 不要写 | 要写 |
| --- | --- |
| 用神月破休囚无力 | 用神现在没力。被月建冲掉，本身又休囚。 |
| 旺相临空不为真空 | 用神空着，但还旺，不算真空；等出空再看实。 |
| 元忌同动接续相生 | 原神和忌神一起动，力量接着传，暂不判原神没用。 |

验收（写进单测或人工清单）：随机抽 10 条命中文案，非术数背景者能复述「谁 / 怎样 / 为什么」三要素。

## 2. 已拍板的选择（原方案待确认项）

| 问题 | 决定 | 理由（白话） |
| --- | --- | --- |
| 权重列（−9~+9） | **不做第一版** | 读者看不懂分数；易被当成「程序判了吉凶」。有力/无力/中和够用。 |
| 数据流 | **B 为主 + A 兜底** | 新卦提交时记下命中了哪几条，以后能回放；旧卦导出时现算，并标「派生、弱证据」。 |
| 吉凶总方向 | **只写用神状态，由汇总写** | 可写用神有力/待时/无根；禁止写成求职/感情等事项结局。 |
| 取象 | **只列标签，不写事项句** | 象随域翻转；标签不得编成所问之事的故事。 |
| 写进 AGENTS | **要** | 交付前确认：人话、只用神、没有事项预言。 |

三条老红线不变：不加解卦步骤；不改 `gua.sql`；新字段旧记录不强制。

## 4. 条目库：固定什么、不固定什么

### 4.1 第一版固定（约 12 条，够用就开）

从原 18 条里先上**程序已能判、书例也撑得住**的：

| id | 人话主题 | 数据从哪来 | 状态 |
| --- | --- | --- | --- |
| R01 | 月令旺 / 相 / 休囚 | `month_strength` | fixed |
| R02 | 月破；休囚月破没力；旺相月破写出月再说 | `branch_interaction` + forces | fixed |
| R04 | 临日可以解开「月破」这层 | 临日 + 月破 | fixed |
| R05 | 日冲静爻：旺→像被叫醒；休囚→日破 | 结构可判 | heuristic（只报结构） |
| R06 | 动爻被日冲，不按「散了」算 | 明动 + 日冲 | fixed |
| R07 | 旬空；旺/动不算真空；真空要月令休囚配合 | `jiazi` + 映射 | heuristic（丑未月标待核） |
| R08 | 只用长生/帝旺/墓/绝；土随水 | `changsheng` | fixed |
| R10 | 变爻主要管本位动爻，不管别人 | `change_board` | fixed |
| R11 | 化吉/化凶几类（回头生克、进退、墓绝空） | `change_board` | fixed |
| R13 | 进退神只认表里七对 | `jin_tui` | fixed |
| R14 | 元神/忌神有力无力摘要 | `forces` | fixed |
| R15 | 用神无根，原神有力也难救 | `forces.primary_rooted` | fixed |

原 R03/R09/R12/R16/R17/R18：第一版可进库但 **config 默认关闭**，文案仍必须 EL15；R16 标 contested。

另两条**固定排除**（也用白话）：

- 互卦、天干合化：不用来找用神。  
- 六神：只当形容词，不单独定吉凶。

### 4.2 明确不固定（程序禁止生成断语）

- 所问事情的结局（成不成、见不见、好不好）  
- 取象编成的事项故事  
- 「某年某月某日事必应」  
- 三合「局成故吉」类定性（只报实局/虚一/破待填）  
- 暗动「所以能救某人/某事」类发挥（只报用神侧结构）

## 5. 页面长什么样（先固定，后推断）

**显示顺序写死：先给人看「盘面上已经能钉死的话」，再给人看「程序/汇总在推断什么」。**

```
解读（主题：用神分析，不是问事预言）
├─ ① 用神盘面要点（固定 / EL15）   ← 先显示
│     预设规则 Rxx 人话（主语必须是用神/原神/忌神/世应）
│     月日结构句
│     用神根基、元忌力度
│     应期通道（相对用神状态，不写「事会在某日发生」）
└─ ② 用神判断摘要（原程序区）     ← 后显示
      针对用神的汇总句（可写有力/待时/无根等）
      各步 notes（取用/旺衰/动变/应期——仍扣用神）
      分层与证伪（条件也必须是用神状态，不是人生情节）
      等候哪些用神条件
      取象标签（若有，无事项吉凶句）
```

为什么这样排：先看钉死的用神盘面，再看本次对用神的判断；**整页都不讲「所问之事会怎样」**。

旧记录没有 `rules_fired`：块 ① 用现算并灰字注明「按当前配置派生」。  
证伪挂在块 ②，且必须是可观察的用神条件（如「用神仍无根」），禁止「若没升职则我错了」这类事项句。
