# 六爻解读 Skill 方案（待审核）

目标：新增一个**解读渲染层 Skill**（拟名 `jingfang-06-interpretation`），把 HTML"解读"区块改成**可配置的预设规则条目 + 程序结论**的固定展示。本方案只做设计，落地待审核。

## 一、定位与硬约束

1. **不是第六个解卦步骤**。`Orchestrator._load` 用 `set(steps) != set(STEPS)` 校验，新增步骤会使全部历史记录失效（PLAN-accuracy 三条硬约束之一）。本 Skill 只消费已冻结的 facts / forces / windows / verdict，不产生新判断。
2. **判断在记录，呈现只回放**。解读区的每条固定文案必须能追溯到：`gua.sql` 表、Skill 章节、或 CASES 书例；渲染端**不现算新规则**，只命中预设条目。
3. **新字段只在新提交时必填**（硬约束三），旧记录必须仍能导出。

## 二、哪些规定适合固定、哪些不宜

判定标准：① 程序可判定（表可查）；② 书例支撑（`CASES.md` 53 例中可对照）；③ 与域无关（不随所问事项翻转）。

## 三、月令 / 日令影响矩阵（解读区的固定表格文案）

月令、日令**不直接决定世应吉凶**：世应关系（世生用、用克世、持世等）是独立维度；月日通过对各爻的作用间接影响。世爻、应爻无任何豁免，与普通爻同一张作用表（自占看世）。

| 对象      | 月令作用                            | 日令作用                                   |
| ------- | ------------------------------- | -------------------------------------- |
| 世爻 / 应爻 | 定旺衰（R01）、月破（R02/R03）、生克、墓绝（R08） | 临值（R04 可解月破）、生克、日破/暗动（R05）、旬空由日柱定（R07） |
| 动爻      | 月破动爻仍能伤爻，出月不破                   | 日冲不论散（R06）                             |
| 变爻      | 月冲变支 = 化破，出月待填                  | 日冲变支同理；变爻不作用他爻（R10）                    |
| 伏神      | 月日可引拔出伏                         | 日冲飞神则伏神易出；飞生伏有用、飞克伏受制                  |
| 空亡      | 真空需月令休囚配合（R07）                  | 旬空由日柱定；冲空则实                            |
| 墓绝      | 月建 target_stage 墓/绝             | 日辰 target_stage + 化墓化绝（R08/R09）        |

**优先级链**（直接沿用 `forces.py` 判定顺序，呈现与判定同源）：  
例外推翻层（R04 临日解月破、旺相月破出月不破、R06）→ 无力层（月破休囚 > 日破 > 真空 > 入墓休囚 > 化退神 > 化回头克 > 休囚非动）→ 有力层（临日月 > 旺相 > 动/暗动 > 化回头生 > 化进神）→ 元忌同动修正（R16）→ 根基层（R15）。

## 四、权重范围（呈现层，与判定层分离）

`forces.py` 目前是三值定性（有力/无力/中和）。为满足"权重范围"，增加**展示性权重**：每个数值对应一条可追溯规则，仅用于解读文本的排序与强调，**不参与吉凶方向计算**；与 `forces.py` 优先级链冲突时显示"需人工核对"，不互相掩盖。

| 日辰   | 临值                                 | +3                  | R04                  |

## 五、输出结构

**Skill 结构**：`skills/jingfang-06-interpretation/`：`SKILL.md`（何时用、如何取条目）、`rules.json`（18 条：id、固定文案模板、出处、status: fixed/contested/heuristic）、`config.json`（呈现开关）。

`config.json`：`enabled_blocks`（规则条目 id 数组）、`show_weight_column`（默认 false）、`contested_style`（badge，固定）。

**数据流（推荐路线 B + 兼容 A）**：

- 路线 B（主）：`synthesis` 提交时增加可选字段 `rules_fired`：`[{rule_id, params}]`。`review.py` 校验 rule_id 存在于 `rules.json`、params 与 facts 一致；随 `rule_version` 冻结，完全可回放。旧记录无此字段不报错（硬约束三）。
- 路线 A（旧记录兜底）：导出时 `view.py` 由 facts+forces 现算命中条目，渲染标注"按当前配置派生"（弱证据样式）。

**reading-data 新增 `interpretation` 对象**：

```json
{
  "config_version": "1.0",
  "preset_blocks": [
    {"id": "R02", "text": "月建{month}冲{branch}为月破；用神{state}，{exception}", "status": "fixed", "source": "月破章"}
  ],
  "conclusions": {
    "forces_lines": [], "primary_rooted": null, "windows": [], "verdict_layers": []
  }
}
```

**模板"解读"区块**改为三个子块：① 预设规则（`preset_blocks`，按 config 顺序，contested 带"需人工核对"徽标）；② 程序结论（forces 表摘要、用神根基、应期窗口、verdict 分层与证伪——把现在 HTML 丢失的 met/unlikely 层补回来）；③ 判断摘要（原 notes/summary 保留）。`falsifier` 移出"行动与等候"，改挂结论块。

## 六、争议与不确定标注清单

1. **暗动**：判据 heuristic（旺相+日冲+静）。争议：休囚被冲书作日破，但"暗动能否生克他爻"书中两说，只报结构。
2. **真空映射**：`forces.py` 硬编码寅卯=土、巳午=金、申酉=木、亥子=火，是"春土夏金秋木冬火"的近似；丑未月（四季土月）不在映射内，须显示"待核"。
3. **月破例外链**：出月不破、实破之日不破、逢合之日不破——三个例外都依赖**未来时间**，解读区只固定规则文案，不预测哪天。
4. **元忌力度平衡**：R16 只判"同动即有力"，忌神远强于原神时书中无量化 → contested，forces-conflicts 3 例 review 类就是这类。
5. **化扶（化合）**：与回头生的力度关系书中无明确等价，权重给 0~+1 区间并标注。
6. **`month_strength` 只有旺/相/休囚三值**，无"囚死"，克入囚地的说法本 Skill 不采用。
