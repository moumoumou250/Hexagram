# 现有数据 × 六表 映射

## 一、现有数据是什么
文件是 SQLite 的**固定盘/查表库**（“京房八宫纳甲固定资料 v5”），只存放不随某次占卜变化的内容。里面**没有任何一次起卦的记录**。
- 字典：wuxing、wuxing_relation、tiangan、dizhi、trigrams、najia、liuqin_rule、yongshen_roles、dizhi_chong、dizhi_he、sanhe、sanxing、changsheng（只有生/旺/墓/绝）、month_strength（旺/相/休囚）、jiazi（含旬空）、jin_tui（7对）、liushen、trigram_fanfu、trigram_change、gua_fanyin
- 卦盘：hexagrams（64卦）、hexagram_lines（384爻）、hidden_spirits（伏神）
- 动变预计算：hexagram_transition（64×64=4096 行）、moving_line_change（每个动爻一行）
- 视图：hexagram_board、hexagram_change、change_board、branch_interaction、integrity_issues

所以两边的关系是：**现有库负责查，六表负责记**。每次起卦，用本卦 + move_mask + 月建 + 日辰去现有库查，查出的结果写入六表。

## 三、现有数据中六表不需要体现的字段
| 现有字段 / 表 | 原因 |
|---|---|
| wuxing.seq/sheng/ke、wuxing_relation、liuqin_rule | 生克和六亲的规则字典，查完只留结果 |
| tiangan 全表、dizhi.seq/polarity/month_no | 静态字典；month_no 也不能代替节气定月建 |
| trigrams.code/image/family/yinyang、hexagrams.upper_trigram/lower_trigram | 排卦中间量，断卦不用 |
| najia 全表 | 已固化进 hexagram_lines |
| hexagram_lines.line_title（初九、六二…） | 爻题文本，断卦不用 |
| hidden_spirits.stem、moving_line_change.base_stem/changed_stem/changed_polarity | 伏神、变爻的天干和阴阳，书中断卦不用 |
| change_board.changed_relative_own_palace | 你在源数据里自己注明了“仅供对照，不用” |
| hexagram_transition.inner_changed/outer_changed/move_positions/l1~l6 | 都能从 move_mask 推出来 |
| hexagram_code 视图、integrity_issues 视图 | 推卦用的工具和自检 |
| dizhi_chong、dizhi_he、changsheng、jin_tui、trigram_fanfu、gua_fanyin、jiazi.xun_head | 规则表，查出的结果已经落在六表的对应字段里 |

| 卦身、六害、沐浴冠带等八位 | 你的库按书中“不验”已经删掉，六表也不设 |

## 四、需要调整或注意的地方
**A. 现有数据能提供，但六表缺少或设计不当的**
1. **t1.gua_type 把两个维度混在一起了**：乾为天既是“本宫”又是“六冲”。建议拆成 `palace_stage`（本宫/一世…五世/游魂/归魂）和 `gua_relation`（六冲/六合/无）。
2. **t1 建议补外键**：`ben_hexagram_id`、`move_mask`、`bian_hexagram_id`，直接对上 hexagrams / hexagram_transition；卦名留作冗余显示。
3. **t1 可补 `gua_change`**：对应 trigram_change，即八纯卦互变时的化生、化克（卦变生克墓绝章），“不论用神衰旺皆以凶推”。
4. **t5.hua_type 一个字段装不下**：一个动爻可能同时是“回头生 + 化进神 + 化长生”。建议照 moving_line_change 拆成 `huitou`、`jin_tui`、`hua_stage`、`hua_chong`、`hua_he` 五列，再加现场计算的 `hua_kong`、`hua_po`。t2/t3/t6 的 hua_type 保留为汇总文本，长度放宽到 VARCHAR(64)。
5. **wang_shuai 的取值要跟你的库一致**：month_strength 只有 旺/相/休囚（未月火、丑月水“有余气”）。六表注释里的“休/囚/死”应改为“旺/相/休囚”，另加一个 `has_yu_qi` 标记，或者写进备注。
6. **t1.bian_gua_type 直接存 relation_change**（六冲变六合 等），不必再拼。

**B. 六表里有、但现有库提供不了的（要起卦时输入，或现场推断）**
- 起卦输入：question、question_category、divine_time、yao_symbol / 动爻（得到 move_mask）
- 要历法计算：month_jian（按节气）、day_ganzhi。库里只有六十甲子，没有万年历。
- **用神取法缺字典**：从“占何事”到“用何六亲”（用神章）库里没有。is_yong_shen、yong_shen_basis 目前只能现场判断。如果你想继续扩充库，这是最值得补的一张字典表。
- 要结合旺衰现场判断：is_an_dong / is_day_po（日冲静爻，旺则暗动、衰则日破）、kong_nature（旺不为空、动不为空等）、化空、化破、出空、出月填实
- 纯断语：select_reason、fu_can_emerge、ke_chu_feng_sheng、tan_sheng_wang_ke、yuan_ji_tong_dong、effective_force、strength、ying_qi_basis、ying_qi、verdict、jian_yao_dong（是否构成阻隔）
