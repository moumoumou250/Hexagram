# 固定库 × 记录查询库映射

## 一、两边各存什么

| 库 | 文件 / 位置 | 职责 |
|---|---|---|
| 固定盘（只读） | `database/gua.sql`；每卦冻结为 `reading-logs/rule-versions/<指纹>/gua.sql`，缓存为 `reading-logs/rule-databases/<指纹>.sqlite3` | 64 卦、384 爻、伏神、4096 动变、同位变爻、冲合、月令、甲子旬空等；**不写卦例** |
| 记录查询库 | `reading-logs/records.sqlite3` | 已校验的起卦输入、主用神指针、结构化判断投影；可用 Markdown 整库重建 |

解卦进度、证据编号、规则引用、待核原因、修订历史和分层应验以 **Markdown**（嵌入 `jingfang-state`）为准。认卦通过且月建、完整日辰齐备后，`records.sync` 把可结构化字段投影进 SQLite。`context.database` 只在 `gua_id`、规则版本、修订号、`record_digest` 一致时返回结果；否则为 `null`，继续用 Markdown 证据。

凡能由 `hexagram_id + move_mask + 月建 + 日辰` 从固定库查出的，**不写入业务表**，由连接时挂载的 TEMP 视图实时关联。

## 二、持久六表

### 1. `gua_record`（每卦一行）

| 字段 | 来源 | 说明 |
|---|---|---|
| `gua_id` | 解卦编号 | 主键，非空 |
| `rule_version` / `revision` / `record_digest` | 冻结指纹、修订号、整份 run JSON 摘要 | 同步与 `context` 一致性门闩 |
| `question` / `divine_time` | 输入 | `question_category` 列已建，**当前不同步**（尚无按占类查询用例） |
| `month_branch` / `day_ganzhi` | 认卦日历事实 | 写入前须能过固定库 `jiazi`；缺项不入库 |
| `hexagram_id` / `move_mask` | 认卦盘面 | `move_mask` 必显式；`0` = 已确认静卦 |
| `yong_*` | focus | `yong_source`∈`base/changed/hidden/month/day`；爻层须带 1–6 位，日月位空 |
| `ying_qi_*` / `verdict*` | timing / synthesis 判断摘要 | 完整窗口与分层证伪留在 Markdown |
| `verified` / `verify_note` | outcome | 仅全体一致的应/未应写入 0/1；部分、未决、冲突为 NULL |

### 2–6. 判断表

| 表 | 主键 | 自动投影 | 靠 `record_judgment` |
|---|---|---|---|
| `yongshen_judge` | `(gua_id, position, layer)` | 有爻位的候选行、`is_selected`、主用 `select_reason` | 飞伏、克处逢生、三合、综合力度等 |
| `yuanji_judge` | `(gua_id, shen_type, position, layer)` | strength 验收后由 `forces` 写入 `effective_force` / `force_reason` | 贪生忘克、原忌同动、`can_act_on_yong` 等 |
| `month_day_judge` | `(gua_id, position, layer)` | 无 | `day_chong_result`、`overall`（不得把 `v_yao.day_chong_hint` 当定论） |
| `kong_po_judge` | `(gua_id, position, layer)` | timing 的 `window` 可合并写入 `ying_qi_channel` | 真空/真破、化出效力、独发独静 |
| `shi_ying_judge` | `(gua_id, item, position)` | 无 | 世/应位填 `position=0`；间爻填实际爻位 |

- 允许字段与步骤白名单见 [`jingfang/review.py`](../jingfang/review.py) 的 `RECORD_FIELDS` / `RECORD_TABLES`。
- 部分唯一索引 `one_selected_yongshen`：同一 `gua_id` 至多一行 `is_selected=1`。
- 布尔类判断字段**无默认 0**，未判断保持 NULL。

## 三、五个 TEMP 视图（每次挂载固定库后创建）

| 视图 | 用途 | 典型步骤 |
|---|---|---|
| `v_gua` | 本变卦、宫世应、冲合变化、旬空、用神角色 | identify 后核对；focus 起 |
| `v_yao` | 六爻纳甲、六神、旺衰、月日作用、旬空月破、同位变、伏神；`day_chong_hint` 仅为候选 | strength / change |
| `v_dong_effect` | 明动爻对其余本爻的生克冲合 | change |
| `v_shi_ying` | 世应支关系 | strength |
| `v_yong_candidates` | base/hidden/changed/month/day 候选；`is_candidate` 与 `is_selected` 分列 | focus |

`rule_scope` 限制当前连接只关联匹配的 `rule_version`，避免用现行规则解读旧记录。

## 四、固定库表 → 视图字段（查阅侧）

| 固定库 | 视图中的用法 |
|---|---|
| `hexagrams` / `hexagram_board` | 本卦爻、世应、伏神入口 |
| `hexagram_change` / `change_board` | 变卦名、动爻位次、同位变、回头/进退/化墓绝 |
| `jiazi` | 日辰成员与旬空 |
| `month_strength` / `branch_interaction` | 月令、日月生克冲合墓绝 |
| `liushen` / `yongshen_roles` / `liuqin_rule` / `dizhi` | 六神、原忌仇、日月取用六亲 |

不进记录库的中间量：互卦推算、天干合化字典、仅对照用的 `changed_relative_own_palace` 等，见固定库注释与解卦 Skill。

## 五、步骤写入约定

| 步骤 | 查阅 | 写入 |
|---|---|---|
| identify | 冻结 `hexagram_*` / `jiazi`；齐备后对照 `v_gua`/`v_yao` | 核心字段齐才入 `gua_record`；冲突/缺项只留 Markdown |
| focus | `v_yong_candidates` | `gua_record.yong_*`；候选行入 `yongshen_judge` |
| strength | `v_yao`、`v_shi_ying` | 自动 `yuanji_judge`；定性项交 `record_judgment` |
| change | `v_dong_effect`、`v_yao` | 明确效力交 `record_judgment` |
| timing | 主用神与已有判断 + 固定冲合/长生 | 摘要入 `gua_record`；通道可入 `kong_po_judge` |
| synthesis / outcome | 引用已完成判断编号 | 方向与摘要入主表；分层与应验细节留 Markdown |

解读 Skill（`jingfang-06-interpretation`）只服务 HTML 渲染，不进规则指纹，也不写业务表。

## 六、版本与迁移

- 记录库：`PRAGMA user_version`，当前为 **1**。空库由 `schema.sql` 持久段引导；后续改列在 [`jingfang/records.py`](../jingfang/records.py) 的 `_migrations()` 中按目标版本注册，并同步提高 `SCHEMA_VERSION`。
- 规则指纹：与每卦快照分开管理；固定库缓存按指纹复用，不可读时改名为 `*.broken` 后重建。
